## ADDED Requirements

### Requirement: Candidate accesses their assessment via an invitation token
The system SHALL expose a `POST /api/auth/candidate/validate-token` endpoint that accepts an invitation token. On success, it SHALL return a short-lived assessment-session JWT scoped to the candidate's assigned assessment. The candidate never sets a password.

#### Scenario: Valid invitation token issues session JWT
- **WHEN** a candidate submits a valid, unexpired invitation token to `POST /api/auth/candidate/validate-token`
- **THEN** the response is HTTP 200 with a JSON body containing a `sessionToken` (JWT) valid for 2 hours

#### Scenario: Expired invitation token is rejected
- **WHEN** a candidate submits an invitation token whose expiry has passed
- **THEN** the response is HTTP 401 with an error message indicating the token has expired

#### Scenario: Tampered or invalid token is rejected
- **WHEN** a candidate submits a token with an invalid signature or malformed structure
- **THEN** the response is HTTP 401

### Requirement: Invitation token is a signed JWT containing candidate and assessment identity
The invitation token SHALL be a JWT signed with HMAC-SHA256, containing `candidateId`, `assessmentId`, and `exp` (7 days from issuance). It SHALL be generated by the backend when a Recruiter creates an invitation (covered in EP-04) — this spec covers the validation side only.

#### Scenario: Token claims identify the correct candidate and assessment
- **WHEN** a valid invitation token is decoded
- **THEN** the payload contains `candidateId` and `assessmentId` matching the intended invitation

### Requirement: Assessment-session JWT scopes the candidate to their assessment only
The session JWT issued after token validation SHALL contain `candidateId`, `assessmentId`, and `role=CANDIDATE`. It SHALL expire after 2 hours. The backend SHALL use this JWT to enforce that candidates can only read and write data belonging to their specific assessment session.

#### Scenario: Candidate session JWT is rejected on non-candidate endpoints
- **WHEN** a candidate session JWT is presented to an endpoint annotated `@PreAuthorize("hasRole('ADMIN')")`
- **THEN** the backend returns HTTP 403

#### Scenario: Session JWT grants access to the candidate's assessment
- **WHEN** a candidate session JWT is presented to a candidate-accessible endpoint
- **THEN** the backend extracts `candidateId` and `assessmentId` from the JWT claims and processes the request

#### Scenario: Session JWT expires after 2 hours
- **WHEN** a candidate session JWT's `exp` has passed
- **THEN** any request using it returns HTTP 401 and the candidate must re-validate their invitation token
